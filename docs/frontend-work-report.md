## 二、基础组件建设（本轮最重要的一批沉淀）

### 1. `components/Select.tsx` —— 自绘下拉（`517fd95`）

**问题**：原生 `<select>` 展开后的选项面板由操作系统绘制（Windows 上是直角白底弹层），CSS 完全无法定制，与深色主题严重违和；这也是用户反复反馈"下拉框不统一"的真正根源。

**方案**：触发按钮（胶囊形 + 自定义 SVG 箭头）+ 展开面板（14px 圆角、深色实底、悬停高亮、选中项 ✓）全部自绘。

**关键技术点**：
- **Portal 到 `document.body`**：聊天头部用了 `backdrop-filter`（毛玻璃），它会成为内部 fixed 元素的包含块，导致面板定位到视口外——实测踩坑后用 `createPortal` 根治（Radix 等组件库的标准做法）。
- 交互完备：点击外部 / Esc / 滚动 / 窗口缩放关闭；键盘可用（方向键 + 回车）；空间不足自动向上弹。
- 所有下拉（模型切换、可见性）已替换，后续新增自动同风格。

### 2. `components/Avatar.tsx` —— 头像三层降级（`89691cd`）

按 `personas.avatar_url`（后端初始表就有的 512 字符字段，无需后端改动）：

```
http(s):// 或 data:image/ 开头 → <img>（加载失败自动降级）
非 URL 短字符串                 → 直接按 emoji 渲染（配淡底色）
空                              → 首字母 + 名字哈希渐变（8 组渐变，同名同色）
```

配套人设表单的**头像选择器**：56px 实时预览 + 32 个预设 emoji 网格 + 图片链接输入。存的就是一个字段，emoji 与图片链接零区别对待。

### 3. `components/Icons.tsx` —— 统一线性图标库（`64db59b`）

**问题**：散落各处的 📌⚙🧠 是彩色 emoji（Windows 上必然彩色渲染，破坏深色主题），✎⧉↻☰ 是字体符号（风格看字体脸色）。

**方案**：9 个图标统一为 1.8 描边、圆角端点的 SVG 线性图标（Pin/Pencil/Copy/Refresh/Gear/Brain/Menu/Stop/Star），与侧栏导航图标一个体系。置顶钉子做了**空心/实心双态**（未置顶空心、已置顶实心+主题紫）。

## 三、视觉与交互体系

### 深色主题全面重写（`5549cc9` → `f64fa79` → `ec0e9ee`，三轮）

- **设计语言**：深空底色（#0a0d14）+ 双团柔光渐变背景 + 靛蓝→紫渐变主色 + 毛玻璃面板分层。
- **动效体系演进**（用户两轮反馈驱动）：
  1. 初版：`transition: all 0.15s`，只覆盖部分属性 → 反馈"生硬"
  2. v2：统一 `all 0.26s cubic-bezier(0.22, 0.8, 0.3, 1)`（easeOutQuart） → 仍反馈"跳动、帧率低"
  3. **终版**：`all 0.32s cubic-bezier(0.4, 0, 0.2, 1)`（Material 标准 S 曲线）——起步柔和、收尾柔和，无突跳感。按下压按保留 0.08s 快响应（触觉反馈不拖泥带水）。
- **防跳动重构**（`f9c134a`）：会话/人设行的悬停操作钮从 `display: none → inline-flex` 改为**常驻占位 + 透明度渐显**。原实现悬停瞬间挤压行内文字、推动下方内容位移（用户实测"密钥与用量点不到"的根因——鼠标移向底部时扫过会话行，按钮从光标下逃走）。修复后悬停时下方元素逐像素零位移（已程序化验证）。

### 布局细节修复

- 头部模型下拉 `min-width: 176px`（`26db227`）：宽度不随选中项文字长短收缩跳动。
- 侧栏底部导航：裸文字链接 → SVG 图标胶囊按钮（悬停浮起 + 边框光晕），并清理了一个会覆盖新样式的重复 CSS 声明。

## 六、多 Agent 协作机制（本前端 agent 主导建立）

建立了仓库根 `AGENTS.md` 通信协议（`ef4316e`），核心是"**提交即广播**"：

- 分工硬边界：前端只写 `web/`，后端只写 `server/` + `deploy/`；发现对方未提交改动不读不碰不提交。
- §二 接口需求单：前端下单（接口/字段/验收标准），后端完成打勾附 commit。
- §三 变更通告：后端改动前端消费的契约必须登记，前端跟进后回执。
- §四 冻结区 + §五 共同契约。

**协议已实际运转三轮**：计费 402/429 通告 → 前端跟进回执；钱包需求单 → 后端交付 → 前端接卡片；提权需求单 → 后端执行。期间还发现并礼让了后端的并行半成品（billing 工作区文件分钟级还在更新时，主动只提交自己的文件）。
