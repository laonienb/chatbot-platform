## 0. 为什么有这一张单

W-1 交付后，实施者**主动上报**一条契约疑义（不是缺陷、是语义冲突）：

> 协议字面上把 `stream_keepalive` 的「缺失」与「显式 false」并列到保守侧 90s，
> 同段又要求「缺键即失败」。我实现成「缺失 ⇒ 拒启动」，与 RB-3 一致但**与那半句有张力**，请裁。

**复核结论：错在架构师，不在实施者。** W-1 单**自身两处相反**——

| 位置 | 原文 |
|---|---|
| W-1 §2 RB-4 | 「`false` **或缺失** ⇒ 取 `model_service_stream_idle_timeout`（**保守侧**）」 |
| W-1 §3 判据 A3 | 「缺 `stream_keepalive` ⇒ 失败」 |

实施者按 A3 做，是**忠实执行**。这正是章程里那条的又一次应验：
**写单的人验收自己的单子，是结构性失效。**

## 1. 裁定要点（协议 v1.7-澄清6 已落文）

两件事**不是同一类**，判据必须分开：

| | 超时键（`features.timeouts` 四项） | 声明位（`features.stream_keepalive`） |
|---|---|---|
| 语义 | 声明**内层预算数值** | **能力放宽位** |
| 缺失的后果 | 「内层 < 外层」断言**根本无从执行**（P2-2 名义闭合、实则空转的病根） | 缺失 = 一个**安全的确定值**（不可能比 90s 宽） |
| 断言还能不能跑 | **跑不了**（静默跳过 = 假装检查过） | **照常跑**，对标 90s |
| **判据** | **缺失 ⇒ 拒启动** | **缺失 ⇒ 按保守侧对标 90s，不拒启动** |

**两条工程理由**（缺一都够，但两条都成立）：
1. 该键随本批**新增** ⇒ 拒启动会让平台**拒绝与任何未升级的旧服务启动**。
   滚动升级时先升平台 = **自造停服**，属运维必然去关掉的检查。
2. 它**不带来任何安全收益**：缺失不可能放宽，拒启动换不到任何保护。

## 2. 改动项

### 2-1 `server/app/llm/model_service_ops.py`：声明位缺失改回保守侧

现实现（`3fa62c9`，`:154-160`）：

```python
if "stream_keepalive" not in features:
    raise ProtocolVersionError(...)
keepalive = features.get("stream_keepalive") is True
```

**改为**：缺失不抛，直接落保守侧（即现 `keepalive = ... is True` 那一行**已经**天然做到
「缺失 ⇒ False ⇒ 保守侧」）⇒ **只需删掉那个 `raise` 块**，并**把注释改对**。

⚠️ **注释必须说明为什么这里与超时键判据不同**（否则后人会再次"统一"成拒启动）——
现 §3.4 明令禁止用注释缩小契约范围，但**也禁止注释与条文相反**。请写成正向理由：

```
# 声明位缺失**不**拒启动（协议 §8.1 硬约束 2 末尾，v1.7-澄清6）：
# 它是**能力放宽位**，只在显式 true 时才把对标放宽到 180s ⇒ 缺失本身即安全的确定值
# （不可能比 90s 宽），断言照常执行、无静默跳过 ⇒ 与显式 false 同待遇。
# 这与**超时键**的"缺失即失败"不矛盾：超时键缺失时「内层 < 外层」**根本无从执行**
# （P2-2 空转病根），而本键缺失不影响断言可执行性。且本键随本批新增，拒启动会让
# 平台拒绝与任何未升级的旧服务启动（滚动升级先升平台 = 自造停服），换不到任何安全收益。
```

**保留不变**：四项超时键的「缺键即失败」（`3fa62c9` 已交付的部分**不动**）。

### 2-2 用例：补"缺失 ⇒ 能启动"这一向（**现在零覆盖**）

## 4. 本单**不做**（需用户裁定）

**`upstream_total_s` 的对标基准**（另见 **W-2**）——协议 §8.1 表称它**仅约束非流式**、
应按「平台读超时口径」对标 `model_service_timeout_total`（`config.py:43`，`120.0`）；
现行代码把它跟流式键一起比 **90s**，靠 `60 < 90` **侥幸通过**。

- **现状更保守**（不会放过任何东西）⇒ **方向安全，不是缺陷**；
- 但**契约与实现不一致**：运维按协议把 total 调到 90–120（协议允许）⇒ 平台**误判违规、拒绝启动**；
- **改它会改行为**（原本启动失败的一批配置会变成能启动）⇒ **留用户裁**，W-2 已备。
