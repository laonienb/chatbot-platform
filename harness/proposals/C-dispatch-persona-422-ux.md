# 派单：创建人设失败时前端只显示「请求失败 (422)」，字段级原因全丢

- 派发方：工作区管家-C（`9ed6b758-…`），2026-10-12 00:10+08:00
- 现象（用户 2026-10-12 00:04 报）：聊天页「新建人设」点保存提示**请求失败**；人设市场**空的**。
- 「市场空」的一半成因是**管家这套预览环境自身的隔离**（预览用仓库外临时库，初始 0 条 personas；共享 `dev.db` 里有 5 条）。已由管家灌入 1 条公开人设，现在 `/market` 可见。**这条不是产品缺陷，别按缺陷修**；但空市场的引导文案见下第 3 点。

## 实测复现（node fetch 直打 8051，同一条命令逐格取状态码）

| 输入 | 状态码 | 后端 `detail` |
|---|---|---|
| `name=""`（名称留空就点保存） | **422** | `[{"type":"string_too_short","loc":["body","name"],…}]` |
| `system_prompt=""` | **422** | 同上，字段是 `system_prompt` |
| `slug="a"` / `"ab"` | **422** | `string_pattern_mismatch`，pattern 要求**最少 3 字符** |
| `slug="MyBot"`（大写） | **422** | 同上 |
| `slug="-ab"`（连字符开头） | **422** | 同上 |
| `slug="李白"` | **422** | 同上 |
| 名称+提示词都填、slug 留空 | **201** ✅ | 自动生成 `persona-2c9143` |
| 同上 + `visibility=public` | **201** ✅ | 会出现在市场 |

⇒ 结论：**后端校验没错**，是用户踩了规则却得不到说明。

## 要修的是前端这两处（`flash-前端-C`）

1. **`web/lib/api.ts` 的 `readErrorBody` 只认字符串 detail**（第 431 行附近那条 `typeof b.detail === "string"` 链）。FastAPI 的 422 发的是**数组** ⇒ 整条链落到 fallback `请求失败 (422)`，**字段名、原因、哪一个输入框全丢了**。要求：
   - 识别数组形态，取 `loc` 末段字段名 + `type`/`msg` 翻成人话（例：`名称不能为空`／`slug 只能用小写字母、数字和连字符，且长度 3–64`），并把错误**显示到对应输入框**而不是只有一句 toast。
   - 非 422 的既有行为不变（`error.code` 优先、`retry_after_s` 那套别动）。
2. **表单侧前置校验与后端规则不一致**（`chat/page.tsx` 约 817 行写着「slug 可选，留空自动生成」，但没写规则）：给 slug 输入框加**与后端同一条 pattern** 的即时校验与长度提示，别让用户提交后才吃 422；名称/提示词为空时禁用保存并说明原因。注意 `createPersona(body: Record<string, unknown>)` 是**无类型 body**，typecheck 抓不到字段错误——这里必须靠测试锁住。
3. 顺带（不是本次缺陷）：`/market` 空态文案「市场还是空的 —— 在聊天页编辑人设，把可见性设为「公开」即可发布」，路径没有错，但既然创建人设的入口藏在聊天页，值得给一个直达按钮。

**验收**：把上面表格里那 6 个 422 输入各配一条用例，断言 `ApiError.message` 是人话且**指明字段**；再断言非 422（401/429/503）路径文案与 `retryAfter` 行为不变。`npm test` 全绿 + `typecheck`/`lint` 干净。

## 给后端的一条契约动作（`flash-后端-C`，轻量）

`422` 的 `detail` 是数组这件事，`AGENTS.md`「三」从没登记过——前端正是因此把它当字符串处理。请按「三」的模板发一条**变更通告**（响应结构类），写清：FastAPI 校验错误 = `{"detail":[{"loc":[…,"body",<字段名>],"msg":…,"type":…}]}`，并说明 `loc` 最后一段才是字段名。这样前端跟进后有据可依，不用下一次再猜。

另请确认一处**历史不一致**（不用改代码，确认即可）：`dev.db` 里存在 `slug='t1'`（2 字符）的人设行，不符合当前 pattern。编辑时前端不带 slug 所以不会报错，但按当前规则这条旧数据是非法的——请判一下是「旧数据豁免、校验只管新建」还是「要迁移补齐」。
